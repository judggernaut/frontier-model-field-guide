Reading a shape: work out what you have before choosing a method

This is the practical skill: look at data and work out what you have. The checklist takes about two minutes and catches nearly everything that would otherwise invalidate the analysis that follows.

A two-minute checkup for a chatbot's response times

Four looks that tell you what kind of data you have before you summarise it.

A thousand response times on a normal axis. A few tall bars on the left and a long empty stretch. You cannot see anything useful, which is itself a clue: the data is heavily skewed.

Put time on a log scale, where each tick is about three times the last. Skewed timing data usually turns into tidy bumps. If it looks like a bell on a log axis, it is roughly lognormal.

Here there are two bumps: answers served from a cache in about 0.3 seconds, and answers generated fresh in about 4 seconds. Two humps mean two populations. Summarise each separately, or the average describes nobody.

Last look: a spike at a wall. The 60 requests that hit the 30 second timeout were recorded as exactly 30. The real tail is longer than the data shows. That is censoring.

The checkup in four moves. Each one changes which summary and which test are honest, which is what the rest of this chapter and the lookup table are for.

Plain wordsLook before you measure

A doctor looks at a patient before prescribing. A summary statistic is a prescription. Before you choose one, look at the data: draw a picture, check whether it leans, check whether there are two groups hiding in it, and check whether something chopped off the top. Most mistakes come from skipping the look.

The two-minute checklist

  1. Plot a histogram. Always. Before any number. Summary statistics hide bimodality, censoring and outliers with total reliability.
  2. Divide mean by median. Above 1.2 is right skewed, below 0.85 is left skewed.
  3. Divide variance by mean for counts. Near 1 means Poisson is plausible. Well above 1 means overdispersed.
  4. Check whether values are whole numbers, and whether they are bounded (at 0, at 1, at n).
  5. Try a log scale. If the shape turns symmetric, you have something lognormal.
  6. Look for a spike at a round number. That is censoring, not data.
  7. Look for two humps. That is two populations.
\[ \frac{s^2}{\bar{x}} \approx 1 \;\Rightarrow\; \text{Poisson}; \qquad\qquad \frac{s^2}{\bar{x}} \gg 1 \;\Rightarrow\; \text{overdispersed} \]The dispersion check for count data: variance divided by mean.
Under the hoodThe checklist as a function
import numpy as np
from scipy import stats

def diagnose(x):
    """Run this before choosing any method. Takes two seconds, catches most errors."""
    x = np.asarray(x, dtype=float)
    n = len(x)
    m, med = x.mean(), np.median(x)
    var = x.var(ddof=1)

    out = {
        "n": n,
        "mean": m,
        "median": med,
        "skew_ratio": m / med if med else float("inf"),   # >1.2 = right skewed
        "var_over_mean": var / m if m else float("inf"),  # ~1 = Poisson-like
        "whole_numbers": bool(np.all(np.abs(x - np.round(x)) < 1e-9)),
        "min": x.min(), "max": x.max(),
        "zeros": int((x == 0).sum()),                     # blocks a log transform
    }

    # Does a log transform fix the skew? Only meaningful for positive data.
    if x.min() > 0:
        out["skew_raw"] = float(stats.skew(x))
        out["skew_logged"] = float(stats.skew(np.log(x)))
        out["log_helps"] = abs(out["skew_logged"]) < abs(out["skew_raw"]) / 2

    # CENSORING CHECK: is there a pile-up at a single value near the max?
    top = x[x >= np.quantile(x, 0.98)]
    if len(top):
        common = stats.mode(np.round(top, 6), keepdims=False)
        out["censoring_suspect"] = bool(common.count > 0.01 * n)
        out["suspect_value"] = float(common.mode)

    return out


lat = stats.lognorm.rvs(0.9, scale=3, size=4000, random_state=0)
for k, v in diagnose(lat).items():
    print(k, v)
# skew_ratio 1.49 -> right skewed, do not report the mean

// A tiny inline PRNG (SplitMix64) so the snippet needs no crates.
// Its draws differ from numpy's, so the random numbers below differ from the Python's.
struct Rng(u64);

impl Rng {
    fn new(seed: u64) -> Self {
        Rng(seed)
    }
    fn next_u64(&mut self) -> u64 {
        self.0 = self.0.wrapping_add(0x9E37_79B9_7F4A_7C15);
        let mut z = self.0;
        z = (z ^ (z >> 30)).wrapping_mul(0xBF58_476D_1CE4_E5B9);
        z = (z ^ (z >> 27)).wrapping_mul(0x94D0_49BB_1331_11EB);
        z ^ (z >> 31)
    }
    /// Uniform on [0, 1).
    fn random(&mut self) -> f64 {
        (self.next_u64() >> 11) as f64 / (1u64 << 53) as f64
    }
    /// Normal draw by Box-Muller.
    fn normal(&mut self, mean: f64, sd: f64) -> f64 {
        let u1 = 1.0 - self.random(); // in (0, 1], safe for ln
        let u2 = self.random();
        mean + sd * (-2.0 * u1.ln()).sqrt() * (std::f64::consts::TAU * u2).cos()
    }
}

fn mean(x: &[f64]) -> f64 {
    x.iter().sum::<f64>() / x.len() as f64
}

fn sorted(x: &[f64]) -> Vec<f64> {
    let mut s = x.to_vec();
    s.sort_by(|a, b| a.total_cmp(b));
    s
}

/// Linear-interpolation quantile (numpy's default method).
fn quantile(x: &[f64], q: f64) -> f64 {
    let s = sorted(x);
    let h = (s.len() - 1) as f64 * q;
    let lo = h.floor() as usize;
    let hi = (lo + 1).min(s.len() - 1);
    let (a, b, t) = (s[lo], s[hi], h - lo as f64);
    if t >= 0.5 { b - (b - a) * (1.0 - t) } else { a + (b - a) * t }
}

/// Sample skewness, as scipy.stats.skew computes it: m3 / m2^1.5.
fn skew(x: &[f64]) -> f64 {
    let m = mean(x);
    let m2 = x.iter().map(|v| (v - m).powi(2)).sum::<f64>() / x.len() as f64;
    let m3 = x.iter().map(|v| (v - m).powi(3)).sum::<f64>() / x.len() as f64;
    m3 / m2.powf(1.5)
}

/// Run this before choosing any method. Takes two seconds, catches most errors.
fn diagnose(x: &[f64]) -> Vec<(&'static str, String)> {
    let n = x.len();
    let (m, med) = (mean(x), quantile(x, 0.5));
    let var = x.iter().map(|v| (v - m).powi(2)).sum::<f64>() / (n as f64 - 1.0);
    let min = x.iter().cloned().fold(f64::INFINITY, f64::min);
    let max = x.iter().cloned().fold(f64::NEG_INFINITY, f64::max);

    let mut out: Vec<(&'static str, String)> = vec![
        ("n", n.to_string()),
        ("mean", m.to_string()),
        ("median", med.to_string()),
        ("skew_ratio", (if med != 0.0 { m / med } else { f64::INFINITY }).to_string()), // >1.2 = right skewed
        ("var_over_mean", (if m != 0.0 { var / m } else { f64::INFINITY }).to_string()), // ~1 = Poisson-like
        ("whole_numbers", x.iter().all(|v| (v - v.round()).abs() < 1e-9).to_string()),
        ("min", min.to_string()),
        ("max", max.to_string()),
        ("zeros", x.iter().filter(|&&v| v == 0.0).count().to_string()), // blocks a log transform
    ];

    // Does a log transform fix the skew? Only meaningful for positive data.
    if min > 0.0 {
        let logs: Vec<f64> = x.iter().map(|v| v.ln()).collect();
        let (skew_raw, skew_logged) = (skew(x), skew(&logs));
        out.push(("skew_raw", skew_raw.to_string()));
        out.push(("skew_logged", skew_logged.to_string()));
        out.push(("log_helps", (skew_logged.abs() < skew_raw.abs() / 2.0).to_string()));
    }

    // CENSORING CHECK: is there a pile-up at a single value near the max?
    let q98 = quantile(x, 0.98);
    let top: Vec<f64> = x.iter().filter(|&&v| v >= q98).map(|v| (v * 1e6).round() / 1e6).collect();
    if !top.is_empty() {
        // the most common value; ties go to the smallest, as scipy.stats.mode does
        let top = sorted(&top);
        let (mut mode, mut count) = (top[0], 0);
        for run in top.chunk_by(|a, b| a == b) {
            if run.len() > count {
                (mode, count) = (run[0], run.len());
            }
        }
        out.push(("censoring_suspect", (count as f64 > 0.01 * n as f64).to_string()));
        out.push(("suspect_value", mode.to_string()));
    }

    out
}

fn main() {
    // lognormal(sigma 0.9, median 3): exp of a normal
    let mut rng = Rng::new(0);
    let lat: Vec<f64> = (0..4000).map(|_| 3.0 * rng.normal(0.0, 0.9).exp()).collect();
    for (k, v) in diagnose(&lat) {
        println!("{} {}", k, v);
    }
    // skew_ratio 1.47 -> right skewed, do not report the mean
    // log_helps true -> it is lognormal, analyse on the log scale
}

The log scale check

QQ plots, once you want more than eyeballing

A QQ plot compares your data's quantiles against a reference distribution's. A straight line means a good match. The way it bends tells you how it differs.

Two humps means two populations

Eval lens
When you see this, stop reaching for statistics and go find the segmenting variable. Split by cache hit, retry status, repo size, task category. Two clean distributions beat one messy one every time, and the split is usually the actual finding.

Censoring: the one that hides

The marathon that closed at six hours

Censoring: when the data stops before the story does.

Finishing times for 3,000 marathon runners. Most finish around five hours. So far, an ordinary bell-shaped pile.

But the course closes at 6:00. The 21% of runners still out there get written down as "6:00". All of them pile into one spike at the wall.

Their real times were later, so the recorded average (5:04) is too optimistic; the true average is 5:13. Dropping them would be worse: you would be averaging only the faster runners.

Agent evals have the same wall. A task stopped at a step limit or timeout is recorded at the cap. Average "steps to solve" then looks better than reality, and the hardest tasks vanish into the spike.

The fix: say how many hit the wall, and summarise with a survival curve (Kaplan-Meier) that treats "still running at the cut" as information, not as a finish time.

Watch out
Timeouts do not create outliers, they create censored data. Every value at the cap is really "at least this much". Your mean, p95 and p99 are all biased downward by an amount you cannot see from the data. Report the censoring rate next to any percentile, or use survival methods. Check for this before reaching for any outlier technique.

For leadersMake "show me the histogram" a habit

The cheapest review step in evaluation is asking to see the raw distribution before anyone argues about the summary. It surfaces three failure modes that no amount of downstream rigour can fix.

Hidden segments

Two humps mean two populations. A change that helps one and hurts the other can net to zero on average. The useful question becomes "which segment moved?"

Silent censoring

A spike at a timeout or token cap means the worst cases were truncated. A model that times out more often can look faster. Insist the censoring rate is reported beside every percentile.

Wrong scale

Latency, cost and token counts are multiplicative. Comparing them on a linear scale overweights the tail. Ratios and log-scale comparisons are usually the honest framing.

Principal asks
"What fraction of runs hit the timeout or the max-token limit, before and after?" If that fraction changed, every latency and length metric in the report is comparing different things, and the headline needs to be redone.
